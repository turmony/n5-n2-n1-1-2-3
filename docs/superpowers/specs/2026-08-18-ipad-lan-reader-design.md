# JLPT iPad 局域网只读阅读器：设计说明

## 1. 目标

为现有 `jlpt-notes` 资料库增加一个适合 iPad 长时间阅读的局域网网页入口。阅读器在 Win11 上手动启动，直接读取当前资料目录，将 Markdown 渲染成 Material for MkDocs 网站，并通过家庭局域网提供给 iPad Safari。

本功能只增加展示层，不改变语法卡、草稿、测验、复习记录、确认入库和固定七天复习周期等既有规则。

## 2. 已确认需求

- 仅在 iPad 与 Win11 位于同一 Wi-Fi／局域网时访问，不支持公网访问。
- Win11 管理员账户继续保持无密码；阅读器不依赖 SMB、Windows 网络登录或云同步。
- 资料保持在现有目录，不搬迁到 OneDrive，也不在资料目录内生成副本或缓存。
- iPad 阅读端严格只读，不提供编辑、删除、上传、下载、确认入库或其他写入入口。
- 展示 `jlpt-notes` 下的全部 Markdown 文件，包括正式卡、草稿、测试题、测试报告和复习记录。
- `jlpt-notes` 下的 JSONL 文件转换为格式化的只读记录列表。
- 正式卡和可识别的草稿、测试题标题必须包含完整 JLPT 编号。
- 支持文件夹层级导航、全文搜索、JLPT 等级筛选、资料类型筛选、明暗主题、字号调整、最后页面和滚动位置恢复。
- 新增、修改或删除资料后，数秒内重建目录和搜索索引。
- 当前阅读页面被修改时，只提示更新，由用户决定何时刷新；其他文件变化可以自动刷新索引和导航，并恢复当前滚动位置。
- 不随 Windows 启动；由桌面快捷方式手动启动。
- 启动后显示控制窗口和 iPad 访问地址；关闭窗口即停止服务。
- Windows 防火墙仅允许专用网络中的本地子网访问，公用网络不开放。

## 3. 非目标

- 不开发原生 iPad App，也不依赖第三方 Markdown 阅读 App。
- 不提供离线缓存；电脑关机、休眠或服务停止时，iPad 无法访问。
- 不发布到互联网，不配置端口映射、UPnP、反向代理或公网域名。
- 不把网站作为资料编辑器、复习执行器或测验作答界面。
- 不修改任何现有 Markdown 或 JSONL 的内容与元数据格式。
- 不追求多用户权限、账户系统、跨设备同步或统计分析功能。

## 4. 技术方案

采用 **MkDocs + Material for MkDocs + 项目内自定义插件**。

职责边界如下：

1. **Material for MkDocs** 负责响应式页面、左右导航、文章目录、明暗主题、搜索界面和基础可访问性。
2. **JLPT 自定义插件** 负责读取现有 JSON 前置元数据、生成统一标题、构建资料分类、转换 JSONL、插入元数据信息栏和生成更新清单。
3. **本地启动器** 负责构建临时站点、监测文件变化、启动只读 HTTP 服务、显示访问地址、检查网络边界和停止服务。

Material 提供成熟的平板与移动端布局、主题扩展和浏览器端搜索；自定义插件只解决本资料库的领域差异，不复制 Material 已有能力。

## 5. 构建与运行架构

```text
jlpt-notes（唯一数据源，只读）
        │
        ▼
JLPT MkDocs 插件
  ├─ 解析元数据和正文
  ├─ 统一标题与分类
  ├─ 生成 JSONL 虚拟页面
  └─ 生成版本与页面哈希
        │
        ▼
Material for MkDocs 构建
        │
        ▼
当前进程的临时站点目录
        │
        ▼
只读 HTTP 服务 ──家庭局域网── iPad Safari
```

站点输出放在当前进程的临时目录中，不放入 `jlpt-notes`、OneDrive 或 Git。停止程序时删除临时目录；异常退出留下的临时目录在下次启动时安全清理。临时站点是派生展示物，不作为学习数据或备份来源。

启动器不直接使用 `mkdocs serve` 的强制浏览器热刷新，而是调用 MkDocs 构建能力，并自行提供静态只读服务。这样可以在当前文章变化时显示更新提示，而不是打断阅读。

## 6. 文件发现与内容解析

### 6.1 文件范围

扫描范围为：

```text
jlpt-notes/**/*.md
jlpt-notes/**/*.jsonl
```

其他扩展名不会出现在网站，也不会通过 HTTP 暴露。隐藏文件、临时文件、备份包和指向资料库外部的链接不纳入构建。

### 6.2 Markdown 前置元数据

自定义插件兼容当前的“`---` + JSON 对象 + `---`”格式。插件按以下优先级提取页面身份：

1. 正式卡使用顶层 `id`、`level`、`title`、`kind` 和 `tags`。
2. 草稿使用 `proposal.id`、`proposal.level`、`proposal.title` 和确认状态。
3. 测试题优先使用元数据 ID；否则从符合规范的文件名提取 ID。
4. 普通报告从文件名、一级标题和正文中提取等级、日期及标题。
5. 无法识别结构时使用相对路径和第一个一级标题，不虚构卡片编号。

原始 JSON 不作为代码显示。插件生成只读信息栏，按存在情况显示：等级、类型、状态、标签、创建日期、更新日期、下次复习日期和来源。缺少某字段不会导致整页失败。

### 6.3 标题格式

- 正式语法卡：`N5-G-0001｜名词句：～です／～じゃありません／～ではありません`
- 草稿：`N4-G-0055｜草稿｜～よう[に]言います：指示、要求`
- 测试题：`N5-Q-0090｜题目标题`
- 无标准编号的测试报告：`N5｜2026-07-27｜综合测试（二）作答报告`
- 无可识别等级的普通文件：使用一级标题，不增加虚构等级或编号。

导航、浏览器标题、搜索结果和正文页标题统一使用同一显示标题。

### 6.4 JSONL

插件通过 MkDocs 的虚拟文件能力为每个 JSONL 生成一个 Markdown 页面，不把原始 JSONL 复制到网站中。页面逐行解析：

- 有效记录以折叠式只读条目显示；
- 常用字段以标签和简表展示；
- 完整记录可以展开查看；
- 单行损坏时仅标记该行错误，不阻断其他记录或整个站点构建；
- 页面不提供原始文件下载链接。

## 7. 导航、搜索与筛选

### 7.1 导航

左侧导航保持 `jlpt-notes` 的现有目录层级。文件夹使用面向学习者的中文显示名，但不修改物理目录：

- `grammar` → 正式语法卡
- `drafts` → 草稿
- `quizzes` → 测试
- `reviews` → 复习记录
- `history` → 修改历史

其他目录保持原名或使用明确的映射。目录内按结构化编号优先、日期次之、文件名最后排序，避免简单字符串排序导致 `N5-G-0100` 出现在错误位置。

### 7.2 搜索

使用 Material 的浏览器端搜索插件，索引以下内容：

- 完整显示标题和卡片 ID；
- 正文中的日文与中文；
- 等级、类型、状态和标签；
- 文件相对路径的可读部分。

搜索配置支持日文和中文。搜索结果开启命中高亮，不接入外部搜索服务，也不上传搜索内容。

### 7.3 筛选

首页生成“资料目录”视图，提供：

- JLPT 等级：N5、N4、N3、N2、N1、未标记；
- 类型：正式语法、草稿、测试题、测试报告、复习记录、历史、其他；
- 标签筛选。

筛选只改变目录展示，不修改资料，也不影响全文搜索索引。

## 8. iPad 阅读体验

Material 主题作为基础，通过小范围主题扩展调整为学习阅读界面：

- 使用 iPad 和 Windows 均可用的系统中文／日文字体，不加载 Google Fonts 或其他公网字体；
- 正文默认采用适合日文例句的字号、行高和段落间距；
- 元数据使用低视觉权重的信息标签，正文保持突出；
- 横屏保留左侧导航与右侧文章目录；竖屏自动折叠导航；
- 提供浅色、深色和跟随系统三种模式；
- 提供有限的正文字号档位，避免任意缩放破坏布局；
- 例句、正确项、错误项、注意事项和代码块保持清晰层级；
- 使用本地浏览器存储记录主题、字号、最后页面和每页滚动位置；
- 支持添加到 iPad 主屏幕并以应用式窗口打开；
- 不注册离线 Service Worker，不缓存学习正文。

主题扩展使用 Material 官方支持的模板覆盖、附加 CSS 和附加 JavaScript机制，不 fork Material 源码，以便后续安全升级。

## 9. 更新机制

启动器定期检查目标文件的相对路径、大小和最后修改时间。检测到变化后：

1. 等待短暂稳定窗口，合并连续保存事件；
2. 在新的临时构建目录中执行完整 MkDocs 构建；
3. 构建成功后原子切换当前站点目录；
4. 构建失败时继续提供上一个成功版本，并在 Win11 控制窗口显示错误；
5. 生成站点版本号以及每个页面的内容哈希。

iPad 页面定期读取轻量版本清单：

- 如果其他页面变化、当前页面未变，页面自动重新载入最新导航与搜索索引，并恢复滚动位置；
- 如果当前页面内容变化，显示“内容已更新”提示，用户点击后刷新；
- 文件被删除且当前正在阅读时，保留当前画面并提示该资料已删除，用户返回目录后不再显示该项。

目标是在文件保存完成后的数秒内提供新版本。更新检测不创建或修改任何学习记录。

## 10. Win11 启动与停止

### 10.1 手动启动

桌面快捷方式启动一个 Tkinter 控制窗口。程序不注册 Windows 登录启动项、计划任务或后台服务。

控制窗口显示：

- 当前状态：准备中、构建中、运行中、更新中、错误、已停止；
- iPad 访问地址；
- “复制地址”；
- “在本机打开”；
- “停止服务”。

关闭控制窗口等同于停止服务。程序停止 HTTP 服务、结束监测并清理当前临时站点。若固定端口被占用，控制窗口显示端口冲突，不静默切换端口。

### 10.2 地址

固定使用项目配置的高位端口，默认设计值为 `8765`。启动成功后显示实际局域网 IPv4 地址，例如：

```text
http://192.168.1.20:8765
```

若电脑存在多个网络适配器，只显示处于专用网络且可用于本地子网的地址。没有可用专用网络时，不开放局域网服务，并说明如何检查 Windows 网络属性。

## 11. 只读与安全边界

### 11.1 HTTP 边界

- 静态服务只接受 `GET` 和 `HEAD`；其他方法返回 `405 Method Not Allowed`。
- 只提供 MkDocs 成功构建后的站点文件，不直接映射 `jlpt-notes` 目录。
- 禁止目录列表和任意路径访问。
- 每个请求解析后的路径必须位于当前临时站点目录中。
- 不提供原始 Markdown、JSONL、Git 目录、项目源码或系统文件下载。
- 页面声明 `noindex, nofollow`，避免被索引器当作公开站点。
- Markdown 中可执行的脚本、事件处理属性、iframe 和危险 URL 会被清除或转义。

### 11.2 Windows 网络边界

- HTTP 服务仅通过固定端口提供。
- 防火墙规则限制为 Windows“专用”网络配置和 `LocalSubnet` 远程地址。
- “公用”网络配置不允许入站访问。
- 首次配置防火墙可能需要一次 Windows 管理员确认，但不要求为 Windows 账户设置密码。
- 启动器只检查并解释网络状态，不自动把公用网络改成专用网络。

由于阅读器不设应用密码，同一受信任家庭局域网中的其他设备理论上也可以打开资料。该风险由“只限专用网络、本地子网、严格只读”共同约束。

## 12. 项目结构

实施边界如下；实施计划必须保持这些模块职责，文件拆分只能在对应模块内部细化：

```text
pyproject.toml                         # MkDocs、Material 与插件入口
src/jlpt_notes/reader/
├─ plugin.py                           # MkDocs 自定义插件
├─ metadata.py                         # 通用元数据和标题提取
├─ jsonl.py                            # JSONL 虚拟页面转换
├─ builder.py                          # 临时站点构建与原子切换
├─ watcher.py                          # 只读变化检测
├─ server.py                           # GET/HEAD 静态服务
├─ network.py                          # 局域网地址和网络配置检查
└─ launcher.py                         # Tkinter 控制窗口与生命周期
reader/
├─ mkdocs.yml                          # Material、搜索、主题功能配置
├─ overrides/                          # 主题模板扩展
└─ assets/                             # 本地 CSS、JavaScript、图标
tests/reader/                          # 单元与集成测试
```

现有卡片读写模块仍服务于正式学习流程。阅读插件使用独立的宽容解析器：它可以展示缺少正式卡字段的普通 Markdown、草稿和报告，但绝不把宽容解析结果写回资料库。

## 13. 错误处理

- 单个 Markdown 元数据异常：显示可读警告页和原始正文，其余页面继续构建。
- 单行 JSONL 异常：只标记该行，不中断文件其余记录。
- 整体构建失败：继续提供上一成功版本，并在控制窗口显示简短错误与日志入口。
- 首次构建失败：不开放局域网地址，避免提供半成品站点。
- 资料目录不存在：启动失败并显示实际检查路径。
- 端口被占用：启动失败并说明端口号。
- 家庭网络不是专用配置：只允许本机预览，并显示局域网未开放的原因。
- iPad 访问超时：控制窗口保留地址，并提供检查同一 Wi-Fi、电脑休眠和防火墙的提示。

错误日志只写到当前会话的临时运行目录，不写入 `jlpt-notes`。日志不记录正文和搜索词。

## 14. 测试与验收

### 14.1 自动化测试

- 正式卡、草稿、测试题、报告和无元数据 Markdown 的标题提取；
- JSON 前置元数据转换和缺失字段容错；
- JSONL 有效记录与损坏行隔离；
- 目录排序、等级筛选、类型筛选和搜索元数据；
- 虚拟文件不暴露原始 JSONL；
- 路径穿越、目录列表和非 GET/HEAD 请求被拒绝；
- 私有网络地址选择与无私有网络行为；
- 文件新增、修改、删除触发构建；
- 构建失败继续保留上一成功版本；
- 临时目录在正常停止时清理；
- 阅读器运行前后资料库文件数量、内容哈希和时间戳完全一致。

### 14.2 视觉与交互验收

- 在接近 iPad 竖屏和横屏尺寸的浏览器视口检查首页、正式卡、草稿、长测试报告和 JSONL 页面；
- 验证日文假名、汉字、中文标点、代码和表格排版；
- 验证浅色、深色、系统主题以及各字号档位；
- 验证搜索中文、日文、完整卡片 ID 和标签；
- 验证最后页面和滚动位置恢复；
- 验证当前页变化只提示、不强制刷新；
- 验证其他页面变化后导航和搜索索引更新；
- 在实际 iPad Safari 上完成同一 Wi-Fi 访问和添加到主屏幕测试。

### 14.3 完成标准

只有在以下条件全部满足后才视为完成：

1. iPad 能通过控制窗口显示的地址阅读全部目标资料；
2. 标题、元数据、导航、搜索和筛选符合本设计；
3. 页面在 iPad 横竖屏下具备稳定、舒适的阅读体验；
4. 更新能在数秒内进入新站点版本，并遵守当前页提示规则；
5. 关闭窗口后局域网地址立即停止服务；
6. 公用网络无法访问；
7. 所有写入型 HTTP 请求被拒绝；
8. 资料库在完整测试前后没有任何内容、时间戳或文件数量变化。

## 15. 依据

- [MkDocs 插件事件](https://www.mkdocs.org/dev-guide/plugins/)支持修改文件集合、导航、页面 Markdown、页面上下文和本地服务行为。
- [MkDocs 配置](https://www.mkdocs.org/user-guide/configuration/)支持自定义资料目录、构建目录和监测路径。
- [Material for MkDocs 自定义机制](https://squidfunk.github.io/mkdocs-material/customization/)支持模板扩展、附加样式和 JavaScript，而无需 fork 主题。
- [Material 搜索](https://squidfunk.github.io/mkdocs-material/plugins/search/)在浏览器本地构建和查询索引，不依赖外部搜索服务。
