# 语法卡页内翻卡导航：设计说明

## 1. 目标

在正式语法卡的阅读页底部增加「上一张卡／下一张卡」导航，让按等级顺序连读多张卡时不必返回目录即可直接翻页。

本功能只改变阅读页的展示内容，不改变资料文件、目录结构、增量构建规则或任何学习数据。

## 2. 已确认需求

- 翻阅范围仅在同一等级内：N4 卡只在 N4 序列内前后翻，N5 末张不会跳到 N4 首张。
- 组内顺序与侧边栏目录顺序一致（现有等级＋编号排序），不引入第二套顺序。
- 按钮显示目标卡的完整编号和标题，例如「N4-G-0002｜「～つもりです」：意图与打算」。
- 仅正式语法卡（`content_type == "grammar"`）显示翻卡栏；草稿、测试题、测试报告、复习记录、历史和 JSONL 页面不加。
- 越界隐藏：序列首张不显示「上一张卡」，末张不显示「下一张卡」。

## 3. 非目标

- 不做键盘快捷键、滑动手势或自动连读。
- 不为其他资料类型提供同类翻页。
- 不记录翻卡行为，不与复习计划联动。
- 不修改 `reader.js` 的更新提示、滚动恢复和筛选逻辑。

## 4. 技术方案

采用**服务端渲染**：`jlpt_reader` 插件在生成语法卡虚拟页面时，把翻卡栏作为页面 Markdown 末尾的受控 HTML 块输出，经现有 `_sanitize_html` 白名单消毒后随页面一起发布。不在浏览器端用脚本生成，页面在无 JavaScript 时仍可点击翻卡。

理由：与目录页（`jlpt-catalog`）的「插件输出原始 HTML → 统一消毒」既有管线完全一致；链接是真实 `href`，Safari 预览、长按和「添加到主屏幕」模式都能正常使用；翻卡内容随页面一起进入增量构建体系，无需新的失效机制。

## 5. 序列定义

- 参与页面：`SourcePage.metadata.content_type == "grammar"` 的虚拟页面。
- 分组键：卡片的 JLPT 等级（与目录、导航、筛选使用的等级字段同源）；等级字段缺失或无法识别的卡（例如元数据损坏、仅按文件夹回退分类的文件）不参与任何序列，其页面不显示翻卡栏。
- 组内排序：沿用 `_source_navigation_key` 现有排序，即编号顺序；序列与侧边栏目录的相对顺序一致。
- 组内排序：沿用 `_source_navigation_key` 现有排序，即编号顺序；序列与侧边栏目录的相对顺序一致。
- 邻接关系在 `on_files` 阶段一次性计算：每张语法卡记录其同等级前驱与后继的（最终路由 URL、完整编号＋标题）。

## 6. 页面呈现

正文与元数据之后输出两格翻卡栏：

```html
<nav class="jlpt-card-pager">
  <a class="jlpt-card-pager__link jlpt-card-pager__link--prev" href="<前驱路由>">
    <span class="jlpt-card-pager__label">← 上一张卡</span>
    <span class="jlpt-card-pager__title">N4-G-0001｜「～までに」：截止时限</span>
  </a>
  <a class="jlpt-card-pager__link jlpt-card-pager__link--next" href="<后继路由>">
    <span class="jlpt-card-pager__label">下一张卡 →</span>
    <span class="jlpt-card-pager__title">N4-G-0003｜「～やすいです」：容易与易发生</span>
  </a>
</nav>
```

- 仅存在一侧链接时输出单项；两侧都不存在（序列只有一张卡）时不输出翻卡栏。
- 样式加入 `reader/assets/reader.css`：左右两格弹性布局，触控目标高度不低于 44px，标题过长时省略号截断，颜色使用现有明暗主题变量，适配 iPad 主屏全屏模式的安全区。
- 链接文本经过与正文相同的 HTML 转义；`nav`、`a`、`span` 与 `class` 属性加入消毒白名单。

## 7. 增量构建正确性

现行的 `_navigation_fingerprint` 已把每张卡的（相对路径、URL、显示标题、编号、类型）纳入指纹：

- 插入、删除、改名任何一张卡都会改变指纹，触发完整重建，翻卡栏随之全部重算。
- 仅修改卡片正文（标题不变）时，只有该卡页面重渲染；邻居页面的翻卡链接指向的编号＋标题未变化，仍然正确。

因此本功能不需要新增失效或失效传播逻辑；需要新增的是断言「增量构建产出的翻卡栏与全量构建一致」的回归测试，防止未来改动破坏这一性质。

## 8. 测试与验收

全部用例先写失败测试再实现：

1. **序列正确性**：三张同等级卡的中间卡页面包含指向前驱与后继的链接，URL 与标题正确。
2. **边界隐藏**：首张卡无「上一张卡」链接，末张卡无「下一张卡」链接；单卡序列不输出翻卡栏。
3. **等级隔离**：N5 末张的页面不含指向 N4 首张的链接。
4. **消毒存活**：翻卡栏 HTML 经消毒后保留 `href`、`class` 与转义后的标题文本；带引号等特殊字符的标题不破坏结构。
5. **增量等价**：在两张卡之间插入新卡后做增量构建，其产出页面的翻卡栏与全量构建结果一致。
6. **样式与触控**：构建产物包含翻卡栏样式，触控目标高度满足 44px（静态检查 CSS 规则存在）。

验收以真实构建产物为准：在本机资料库的 N4 序列上抽查第一张、中间一张和最后一张的页面。
