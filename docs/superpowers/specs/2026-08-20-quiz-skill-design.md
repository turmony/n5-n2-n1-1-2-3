# JLPT 出题与判分 Skill 设计

- 日期：2026-08-20
- 状态：设计经用户逐节确认，待复核
- 背景出题资产：`jlpt-notes/`（grammar 卡 120 张 N4＋既有 N5、quizzes 下 papers/answers/questions/results/attempts.jsonl）

## 1. 背景与目标

用户用 Claude Code 从本地语法卡片生成 JLPT 题库试卷，历史上反复出现两类质量事故：

1. **机械性笔误**：排序题推荐语序数字串抄错、无效排列、题卡 ID 覆盖冲突、题面与答案不同步；
2. **语义性错误**：答案本身选错、题目日语不自然、干扰项也能成立。

本设计把出题与判分流程固化为两个项目级 skill，用「确定性脚本校验 + 新上下文盲测审题」双层质检拦截上述事故，并建立历史错题回归集，使 skill 可随使用低成本进化。

**历史事故清单**（回归集的种子，全部真实发生过）：

| 事故 | 出处 |
|---|---|
| 答案文件推荐语序数字串笔误（3142 误作 3412 等 3 处） | 覆盖卷六第 21/23/24 题（已事后修正） |
| 无效排列待确认 | 覆盖卷六第 21 题（作答侧） |
| 题卡 ID 覆盖冲突、被迫重编号 | 覆盖卷三/卷四 |
| 题目缺陷待确认（3 处） | 覆盖卷四 Q1/Q21/Q22 |
| 跨卷重复题（查重靠人工发现） | 覆盖卷六出题时 1 处重写 |

## 2. 已确认的需求决定

| # | 决策点 | 结论 |
|---|---|---|
| 1 | skill 范围 | 两个独立 skill：quiz-generate（出题）、quiz-grade（判分） |
| 2 | 选卡策略 | 错题驱动自动提议 + 用户确认/手改；也可完全手动指定 |
| 3 | 卷面结构 | 默认 34 题＝形式选择 20＋句子排序 7＋篇章完形 7，参数可覆盖；错题驱动只影响选卡 |
| 4 | 质检失败处置 | 分级：机械错误自动修复后重验；语义分歧只标记、用户裁决，不擅改题意 |
| 5 | 语义质检强度 | 单盲测（1 个新上下文子代理）＋分歧题卡片复核 |
| 6 | 硬性要求 | 题必带答案：三件套（试卷/答案/题卡）同次生成、同套质检、三方一致性强校验，不合格不交付 |
| 7 | 判分报告 | 参照现有 N4 成绩报告格式，全部题目都含解析（对题给要点、错题给完整诊断） |

## 3. 总体架构

```
.claude/skills/
  quiz-generate/
    SKILL.md                       # 出题流程指令（选卡提议→生成→质检→交付）
    scripts/validate_quiz.py       # 机械校验器（uv run，纯标准库，hook 兼容）
    scripts/tests/                 # pytest 回归测试
    scripts/tests/fixtures/        # 历史事故重建样例
    references/report-checklist.md # （可选）校验项速查
  quiz-grade/
    SKILL.md                       # 判分流程指令
    references/result-template.md  # 成绩报告模板（固化现有六卷格式）
```

- 命令：`/quiz-generate`、`/quiz-grade`；SKILL.md 描述含中文触发词（“出卷/出题/判分/成绩”），支持自然语言自动加载。
- 参数（`$ARGUMENTS`，自然语言）：级别（默认 n4）、结构覆盖（如「排序 10」）、选卡指定（如「G30-60」「のに专场」）。未给参数走默认与错题驱动。
- 不做 hook 硬门禁、不做多代理扇出（详见「非目标」）；校验器从第一天即 hook 兼容（非零退出码＋结构化输出），未来加装零改造。

## 4. quiz-generate：出题流程

### 4.1 选卡提议（先提议、后动笔）

输入三源：

1. `quizzes/attempts.jsonl`：按卡聚合 error_tags 频次；
2. `quizzes/results/*.md`：最近各卷薄弱区结论（连败题型、修饰链等）；
3. `grammar/<level>/` 卡片 `next_review` 到期情况（落实 AGENTS.md 第 6 条）。

产出「本卷覆盖提议」表：卡号｜考点｜出题侧重｜分配题型｜选题理由（错 X 次/连败 N 卷/到期）。呈现给用户确认或修改后才生成。用户在参数中手动指定卡片时跳过提议。

### 4.2 生成三件套（一次写全）

| 产物 | 路径 | 内容 |
|---|---|---|
| 试卷 | `quizzes/papers/YYYY-MM-DD-<level>-<主题>-test-N.md` | 盲答用，不含答案；含作答说明、时间建议、答案填写区、排序规则速览；序号 N 在「级别＋系列」内接续（如 coverage 系列，与现有 n4-coverage-test-1～6 一致），建议文件名在选卡提议环节一并确认 |
| 答案文件 | `quizzes/answers/<试卷名>-answers.md` | 每题：题目、翻译、考点卡号、正确项、正确接续（粗体空格成分）、四个选项逐项解析；排序题另附推荐语序＋逐块排序理由 |
| 题卡 | `quizzes/questions/<LEVEL>-Q-XXXX.md` | JSON frontmatter：id/revision/level/item_type/prompt/options/correct_option/correct_explanation/option_explanations；编号接续该级别既有最大号 |

约束（写入 SKILL.md）：仅文法三题型；只考 status=confirmed 的卡；每道四选一必须解释正确项与其余三项（AGENTS.md 第 7 条）；每题恰一个最佳答案。

### 4.3 质检管线（双层）

**第一层：机械校验**（`uv run scripts/validate_quiz.py`，确定性，零 AI 判断）

| # | 检查项 | 拦截的历史事故 |
|---|---|---|
| 1 | 题卡 ID：新卡号连续、不与全库冲突（接缝）；frontmatter JSON 合法、必填字段齐全 | 卷三/卷四 ID 覆盖冲突 |
| 2 | 排序题不变量：推荐语序是 1–4 合法排列；解析文字逐块编号顺序与语序串一致；正确项＝语序串在 ★ 位的数字（★ 位从试卷解析，不写死第二空） | 卷六 3 处语序数字串笔误、无效排列 |
| 3 | 三方一致：试卷题干/选项 ↔ 题卡 prompt/options ↔ 答案文件题目/选项/correct_option | 答案抄错、选项不同步 |
| 4 | 考点卡号存在且级别匹配 | 引用不存在的卡 |
| 5 | 结构：题量符合参数（默认 34=20+7+7）、题号连续、每题选项恰 4 个 | 结构性漏题 |
| 6 | 跨卷查重：新题干对全库题卡 prompt 做归一化比对（去标点/空白），精确重复报错；高度相似列入盲测员重点 | 卷六重复题 |
| 7 | 答案完整性：答案文件覆盖试卷全部题号、每题有正确项与四项解析 | 「题必带答案」落地 |

输出：`--json` 结构化报告＋人读摘要；任何检查失败退出码 1（hook 兼容）。

**第二层：盲测审题**（Agent 工具派发新上下文子代理）

- 输入：试卷全文直接贴入 prompt（不给文件路径，防翻到答案）＋语法卡目录路径（可自由查阅）；明令禁读 `quizzes/answers/` 与 `quizzes/questions/`（题卡含正确答案）。
- 第一步：独立整卷作答（排序题给语序＋理由），输出逐题答案与信心；
- 第二步：仅对与答案 key 分歧的题，重读对应考点卡后二次作答，输出最终立场与理由；
- 产出：分歧清单（题号｜双方答案｜盲测理由｜复核立场）＋查重疑似项复核。

**分级处置**：机械错误 → 自动修复 → 重跑校验，上限 3 轮，仍失败上报停止；语义分歧 → 只标记不改题，全部经用户裁决后才定稿。

### 4.4 交付

质检全绿（机械）＋语义分歧处置完毕 → 汇报三件套路径与质检摘要 → 按既有风格 git 提交（`feat: 添加 …`）。

## 5. quiz-grade：判分流程

1. **读作答**：从试卷「答案填写区」读取学习者提交（含 `?` 不确定标记）；
2. **判分**：对照答案文件逐题判定；排序题按完整句是否自然、语法成立计分，不做数字串硬比对；疑似无效排列/笔误标「待确认」并沿用卷三第 23 题先例的处理口径；
3. **成绩报告** `quizzes/results/<试卷名>-result.md`，五段式（模板固化到 references/result-template.md）：
   - 头部说明：判卷说明、计分标准、待确认事项、出题侧更正记录；
   - 成绩概览：三部分分项得分与百分比、全卷得分、跨卷曲线（自动汇总历史 results）、错题清单、不确定清单；
   - 全部考点清单表：全部题逐题列（题号｜考点卡｜考点｜✓/✗）；
   - 逐题全解析：**全部题目**，每题六要素——题目、翻译、你的答案（＝正确/✗）、接续规则（含卡号）、意思、解析；对题给要点、错题给完整诊断；
   - 薄弱区结论：连败题型/卡片，作为下次 quiz-generate 选卡提议的直接输入（反馈闭环）；
4. **记录**：追加 `quizzes/attempts.jsonl`（沿用现有 schema：question_id/revision/item_type/selected_option/is_correct/uncertain/error_tags/date）；
5. **提交**：按既有风格 git 提交（`feat: 记录 …`）。

## 6. 回归集与进化循环

- fixtures 以**历史事故重建样例**为准（仓库内文件多已事后修正，直接跑旧卷抓不到原缺陷）：在正确卷面上重引入语序数字串笔误、无效排列、ID 冲突、三方不一致等，逐条断言校验器必须报错；
- 六套现存旧卷整卷跑一遍校验器，验收「已知缺陷全部能被抓」（现存文件中已修正的事故以重建样例覆盖）；
- 进化：新漏错 → 用户说「把这次的坑加进 skill」→ SKILL.md 清单加条目＋校验器加断言＋回归加 fixture → 重跑全部历史 fixture 证明无退化。

## 7. 测试与验收

- `uv run pytest`（脚本用纯标准库；pytest 经 uv 环境执行，遵循「Python 一律 uv run」项目约定）；
- 验收标准：①回归测试全绿（每个历史事故样例被对应检查项拦截）；②六套旧卷整卷校验——已修正的事故不再误报，**仍留在文件中的已知缺陷（如卷四 Q1/Q21/Q22 待确认项）应被准确报出**；③quiz-generate 真实出 1 卷全流程走通；④quiz-grade 对该卷判分走通并产出五段式报告。

## 8. 非目标（升级路径，不在本次范围）

- settings.json hook 硬门禁（PostToolUse/Stop）——若日后发现 skill 指令被漏跑再加，校验器已兼容；
- 双盲测/多代理扇出、skill-creator 评测——与已确认的「单盲测」决策冲突，暂缓；
- 出题/判分以外的卡片管理流程（确认入库、复习周期等维持 AGENTS.md 现状）。
