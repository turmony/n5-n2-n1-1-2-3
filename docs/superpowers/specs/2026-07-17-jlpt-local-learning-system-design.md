# JLPT 本地学习循环系统：设计说明

## 1. 目标与范围

建立一个以本地 Markdown 为核心的长期日语学习系统，覆盖 N5 至 N2，并为未来 N1 留出扩展空间。系统形成以下循环：

1. 学习者观看出口仁老师的课程后，用中文文字输出自己吸收后的理解。
2. Codex 检查理解、接续、例句和疑问，补充语义限制、易混项与 JLPT 考点。
3. 经学习者确认后，内容成为本地结构化知识卡。
4. 知识卡按固定的七天间隔复习；漏复习进入温和的逾期队列。
5. 系统按 JLPT N2 公开题型与命题风格生成原创测试题，保存作答、解释干扰项并分析错因。

听力永久不在本系统范围内。测验范围为 JLPT N2 的全部非听力题型：词汇、语法、阅读。

## 2. 核心原则

- **本地优先：** 所有长期学习数据保存在可读、可迁移的 Markdown 与结构化日志中。
- **学习者输出优先：** 学习者的原始理解是学习证据，不会被校对结果覆盖。
- **确认后入库：** Codex 的校对先生成待确认卡；只有收到“确认入库”后才创建正式卡并启动复习周期。
- **固定复习节奏：** 所有正式卡在确认或实际复习完成日后的第七天到期。答错和“不确定”不增加额外复习。
- **JLPT 风格而非真题复刻：** 题目使用原创文字，参考 JLPT 官方公开题型、能力目标与干扰项风格；不复制官方试题，也不声称为真题。
- **可追溯：** 卡片、题目与作答均可追溯到唯一 ID、版本与时间。

## 3. 资料库结构

```text
jlpt-notes/
├─ grammar/                 # 已确认的语法卡，按 N5 至 N1 分层
├─ vocabulary/              # 已确认的词汇卡
├─ reading/                 # 阅读材料与题目素材（后续扩展）
├─ drafts/                  # 学习者原始输出和待确认校对结果
├─ reviews/                 # 追加式复习记录
├─ quizzes/                 # 题目定义和作答记录
├─ analytics/               # 派生统计与日报/周报
├─ history/                 # 面向人的卡片修改说明
├─ schemas/                 # 字段规范、版本迁移与校验规则
├─ backups/                 # 只读备份包
└─ README.md                # 使用说明与今日操作入口
```

### 3.1 数据表达

语法卡和词汇卡采用“结构化前置元数据 + Markdown 正文”。默认以前置 JSON 保存字段（JSON 是 YAML 1.2 的可读子集，因此可作为离线、零依赖的 YAML 兼容格式），正文保存便于学习的解释、例句和对比。

正式卡至少包含：

- 永久 `id`；
- `level`、`source`、`status`；
- `card_revision`、`schema_version`、创建和修改日期；
- `next_review` 与复习摘要；
- 关联的易混项、标签和来源；
- 本次修改的简要原因。

复习和作答数据使用追加式日志。日志中的关联只使用永久 ID 和卡片版本，不依赖文件名。

## 4. 学习输入与校对

学习者可按以下模板发送文字：

```text
等级：N3
课程序号：第 12 个语法点
语法：～わけではない
我的理解：……
视频中的例句／我记下的例句：……
我的疑问：……
```

课程序号用于追溯课程来源；系统另行生成永久内部 ID。一次可提交一个或多个语法点，每个语法点单独进入草稿。

校对分为四类：

1. 理解结论是否准确；
2. 接续是否完整、是否存在例外；
3. 例句是否自然、语境是否成立；
4. 需要补充的语义限制、易混语法与 JLPT 考点。

草稿保存原文和校对结果。确认入库后，正式卡从确认日开始安排首次复习；草稿长期保留，不被覆盖。

## 5. 复习与缺席恢复

### 5.1 固定七天周期

- 正式卡首次到期日为确认日加七天。
- 完成任何一次复习后，下次到期日为实际完成日加七天。
- 若原定 7 月 8 日复习、实际在 7 月 10 日完成，则记录为逾期完成，下次为 7 月 17 日。
- 答错或标记“不确定”只更新错因、掌握度和后续出题权重，不会插入提前复习。

### 5.2 每日简报与温和滚动

Codex 的定时任务每天只读本地资料库，生成今日清单。每日复习上限由学习者配置。

- 优先级：逾期卡优先于当天到期卡；同级中优先错误更多、标记过“不确定”或更久未复习的卡。
- 未排入或未完成的卡保留在逾期队列，不会消失或被视为完成。
- 简报显示已排入数量、逾期数量、因上限未排入的数量、薄弱题型、建议练习与待确认词汇卡数量。
- 复习先要求主动回忆含义、接续和用法，再显示正式卡和补充内容。

## 6. 测验范围与出题规则

### 6.1 N2 非听力题型

系统支持以下 N2 题型：

- 词汇：汉字读音、表记、构词、语境规定意义、近义替换、用法；
- 语法：语法形式选择、句子重组、篇章语法；
- 阅读：短篇、中篇、长篇、综合理解、主张理解、信息检索。

JLPT 官方公开资料列出这些 N2 题型；系统会定期在实现维护中核对官方说明与样题的变化。

### 6.2 两类题源

- **已学知识题源：** 使用已确认的语法卡，面向学习和固定周期复习。
- **N2 基准题源：** 不要求学习者预先录入词汇，可直接提供 N2 词汇题与阅读题，用于摸底和能力检测。

每道题都记录目标等级、题型、考查卡或能力标签、语境、选项、答案、每个干扰项的设计理由、生成时间和依据的卡片版本。题目文本原创。

### 6.3 作答反馈

每次提交答案后，系统必须：

1. 判定正误；
2. 说明正确项为什么成立；
3. 对其余三个选项逐一说明错误原因；
4. 保存选择的错误项、题型、错因与“不确定”标记；
5. 用历史统计调整未来题目比例，但不改变复习日期。

对句子重组和篇章题，也应将反馈映射到四个可选结果或语块位置，保证错误路径可解释。

## 7. 词汇卡策略

词汇测试不要求学习者先录入词汇。答错的词汇自动生成“待确认词汇卡”，保留错题现场、正确释义、例句、错误选项和错因。

学习者可对一组候选卡执行“全部入库 / 选择入库 / 仅保留统计”。只有确认入库的词汇才成为正式卡并进入固定七天复习；未确认项目只保留错题统计。

## 8. 错题分析与报告

每次作答为不可覆盖的事件，至少关联题目版本、卡片版本、学习者答案、正确答案、日期和确定性。

分析采用双层标签：

- **题型：** N2 六类词汇题、三类语法题、六类阅读题；
- **错因：** 读音/表记、词义混淆、构词判断、接续错误、语义细微差异、上下文衔接、句子结构、主旨判断、细节定位、信息检索、粗心或不确定。

周报比较近期与历史的正确率，指出进步、停滞与高频错误。错题统计影响未来测验类型和标签权重，不改变七天复习周期。

## 9. 版本、校验与恢复

### 9.1 双层版本

- `card_revision`：卡片内容改变时递增；
- `schema_version`：存储字段或格式改变时递增。

卡片修订保留永久 ID、递增内容版本，并在 `history/` 写入人可读的修改说明。原始草稿、复习日志和作答日志不覆盖。

### 9.2 本地历史与备份

- 整个资料库使用本地 Git 记录差异和回退点；
- 仅在明确的入库、修改、迁移或备份操作中写入数据；每日简报保持只读；
- 入库前校验必填字段、日期、重复 ID、失效引用和版本号；
- 定期生成只读备份包，用于误删或格式迁移失败后的恢复。

## 10. 非目标与后续边界

- 不包含任何听力学习、听力题目或听力统计；
- 不复制 JLPT 官方题目、音频、受版权保护的阅读材料或答案；
- 不把动态答错自动视为已学词汇；必须由学习者确认后才进入复习；
- N1 为未来扩展层：沿用 ID、版本、题型标签和资料库结构，不重构既有数据。

## 11. 验收标准

系统完成后应满足：

1. 可保存并区分学习者原始输出、校对结果与确认后的正式卡；
2. 可在任何日期计算到期和逾期卡，并按照固定七天及每日上限规则生成清单；
3. 可生成、记录和解释 N2 非听力题型的原创练习题；
4. 每道四选一题均能解释正确项和三项干扰项；
5. 可按题型、错因、等级和语法/词汇功能汇总错误；
6. 修改卡片后可追溯版本、校验数据并从本地历史或备份恢复。
