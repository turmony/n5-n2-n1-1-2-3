## 获取课程材料

- 以原视频的日语讲解、日语字幕和板书为课程依据。字幕可能有同音错字、助词遗漏或断句错误，必须校对；不能把自动字幕当成准确原文。
- 每课优先提取 **0:01 的实际视频画面**，逐张目视检查是否清晰显示本课接续。
- **每个语法卡必须包含两张原视频图片：一张接续图和一张例句图。** 接续图用于展示本课接续及必要讲解板书；例句图用于展示视频中的课程例句，通常从视频后半部分的例句页提取。两张图分别标明真实时间、原图尺寸及裁切区域；不得用同一张图重复充当两类图片。
- 如果该时点是片头、遮挡严重或接续不完整，寻找其他清晰时点，必要时补充截图，标注各图实际时间，不把其他时点标成 0:01。
- 截图必须来自原视频，不得用封面、AI 重绘或根据字幕生成的示意图冒充。固定左上角，通过收拢右下角裁去底部空白与右侧多余画面；保留接续和必要板书，不重绘文字。记录原图尺寸与裁切区域。
- **截图不能仅仅显示接续内容。** 必须同时保留本课有助于理解的含义说明、例句或易混项等必要板书；不能为了裁掉人像，把画面缩成只有接续表的小块。此规则由学习者于2026-09-12补充。
- **在保证教学内容完整、清晰的前提下，尽可能裁剪掉空白和人像。** 优先选择老师让开板书、遮挡更少的实际时点，再固定左上角收拢右下角；若文字与人物重叠，优先换时点或用独立截图互补，不抹除人像、不重绘、不拼接。仍无法避免的遮挡应明确注明，不能用裁断主要板书来换取无人像画面。
- 保存截图文件、视频网址、实际时间和必要的获取记录。文档使用可追溯的图片引用，不依赖临时下载地址。
- 缺失字幕可尝试检查原视频画面或其他可用原始材料；关键内容仍无法核实，进入问题处理流程。

### 网页检索与正文抓取工具

- 抓取网页信息统一使用本机已安装的 Crawl4AI（当前版本 0.9.3），命令行入口为 `crwl`。`crawl4ai` 是安装包名，不是可执行命令；不要直接运行 `crawl4ai`。
- Crawl4AI 只替代网页获取工具，不改变独立验证标准：原视频之外每课仍至少核对两份互相独立的教学资料，并优先选择日本的日语教学机构或日语教师提供的日文正文。
- 搜索引擎页面只用于发现候选网址；搜索摘要、AI 摘要和结果标题均不得作为教学证据。必须用 Crawl4AI 打开并读取目标页面正文，再记录实际支持的接续、含义、限制与易混项。
- 若搜索页触发验证码或目标站点无法抓取，可改用另一公开搜索入口、目标站点搜索接口或浏览器目视核验；不得绕过登录、付费墙、验证码或访问控制。
- Crawl4AI 获取结果放在仓库外的临时缓存目录（如下面的 `$crawlCache`）或已确认被 Git 忽略的目录中，不提交搜索页、网页镜像或原始缓存；正式卡只记录来源链接、核对日期和对应支持要点。
- Crawl4AI 抓取失败且关键内容无法通过其他公开正文可靠核实的课程，继续按问题处理流程执行，不交付完整卡片。

常用 PowerShell 命令如下。将示例网址替换为实际要核对的教学正文网址；保存文件前先创建缓存目录。

```powershell
# 查看抓取参数
crwl --help

# 检查安装及浏览器抓取能力（会联网执行测试）
crawl4ai-doctor

# 抓取网页并在终端输出 Markdown
crwl crawl "https://example.com" -o markdown

# 创建仓库外的临时缓存目录，并保存 Markdown 正文
$crawlCache = Join-Path $env:TEMP "jlpt-crawl4ai"
New-Item -ItemType Directory -Force -Path $crawlCache | Out-Null
crwl crawl "https://example.com" -o markdown -O (Join-Path $crawlCache "source.md")

# 绕过缓存重新抓取，输出详细日志以便排查失败
crwl crawl "https://example.com" -bc -v -o markdown -O (Join-Path $crawlCache "source-fresh.md")

# 保存 JSON 结果；保留日文字符，便于阅读
crwl crawl "https://example.com" -o json --no-json-ensure-ascii -O (Join-Path $crawlCache "source.json")
```

### 独立验证步骤

1. **优先搜索日本的日语教学网站**，优先阅读日本的日语教学机构、日语教师提供的日文原文；再视需要补充其他可靠资料。
2. 原视频之外，每课至少核对两份独立教学资料。原视频的转载、同一内容的复制或翻译不能充当独立证据。
3. 打开并阅读来源正文，不以搜索摘要代替验证，不仅凭网站名称或域名认定可靠。
4. 首先核对接续：词类、辞书形／ます形去ます／て形／た形、名词是否加の、な形容词是否加な或だ、礼貌体、否定与过去形式、后接名词时的变化。
5. 再核对含义、语义边界、后项限制、常见搭配、自然例句、易混项和 JLPT 考点。
6. 资料有分歧时检查是否属于不同用法、语体、适用范围或教学简化，不按来源数量简单投票，也不把“通常”改写为“必须”。
7. 在卡片中记录具体来源链接、核对日期和各来源支持的要点。区分原课程内容与外部补充，不虚构已查阅的来源。

## 正文格式与接续写法

待确认内容参考已有正式卡的结构和表述，完整到可以审核后转为正式卡；不要擅自重做一套不熟悉的格式。

推荐顺序：

1. 课程标题与待确认状态。
2. 学习者原始输出及理解校对（有实际输出时）；没有时使用“视频学习资料整理”；原视频截图放在此节，附来源、实际时间、裁切说明和图片链接。
3. 核心与接续（之后按中文释义合并结果编写“场景演示”）。
4. 语义边界、适用条件及后项限制。
5. 例句与中文译文。
6. 易混项及 JLPT 考点。
7. 来源与复核记录。

接续必须具体、便于理解，沿用已有内容的写法，例如：

- 动词辞书形＋……
- 动词ます形去ます＋……
- 动词て形＋……（注意て形已含て／で，不重复添加）
- 动词た形＋……
- 名词＋の＋……或名词＋……（接续式不加“直接”二字；必要时另注不加「の」）
- な形容词词干＋な／だ＋……（按本课真实规则选择）

必要时用“类型｜接续规则｜示例”的表格，并给出词形变化实例。不能只写笼统的“普通形”而隐藏重要例外；也不能把核心、少见变体和补充用法混成冗长的主表。

**接续表的“接续规则”栏必须写具体类型及其词形。** 使用“动词”“い形容词”“な形容词”“名词”等直观名称，不用 A、B 等抽象符号代替具体接续。原视频中的 A、B 仍保留在大号总接续及其解释中，但不写进逐词类展开的接续规则栏。

**接续表必须按词类逐行书写，一种实际接续占一行。** 动词和い形容词等不同词类不得合并在同一行；本课有几个可能接续，就写几行。例如某课有名词直接接续一种，以及“普通形＋の”的动词、い形容词、な形容词、名词四种接续，表格就写五行。不得遗漏实际出现的接续，也不得为了凑齐形式虚构视频未出现的类型或名称，例如没有依据时不得添加“名词（从句）”。同一词类有两种不同接续时，“类型”栏可以重复写该词类，具体差异写在“接续规则”栏，不另造类型名称。

按学习者补充的展示要求，“核心与接续”开头先用大号粗体显示总接续（Markdown可用二级标题加粗），再解释符号、含义和具体接续。例如本课规则确实允许时，可写「【普通形（[だ]，[だ]）】」，并注明两个「[だ]」依次对应な形容词和名词的现在肯定形，表示「だ」可有可无。此例不能套用到不允许省略「だ」的其他语法，必须逐课检索复核。表格“类型”只写“动词”“い形容词”“な形容词”“名词”等词类；现在肯定、过去、否定及其特殊变化写在“接续规则”中，不写进类型名称。

**总接续包含多个可能形式时，每个可能形式必须单独占一行，并继续使用大号粗体显示；不得用斜杠把多个可能形式串在同一行。** 各行顺序严格按照原视频板书。属于同一个可能形式内部的可省略成分、对应汉字注释或紧密配对结构不再拆行，例如「に[して]」和「をこめて(込めて)」各自保留在同一行。

**总接续必须严格按照原视频板书书写。** 不得把外部资料中的常见变体、可选助词或自行概括的成分加入总接续；例如视频写「に対して，B」时，不得改写成「に対して（は），B」。确需补充视频外变体时，放在总接续之后单独说明并标明为外部补充，不得混入视频接续。

**原视频接续中的结构符号必须保留。** 视频使用 A、B 等符号标示前项与后项时，卡片的大号总接续及其解释应保留这些符号，方便学习者对应句子结构；逐词类展开的接续表则按上文规则使用具体类型，不在“接续规则”栏重复 A、B。

学习者提供礼貌体语法时，核心和接续也保留礼貌体。语法形式优先写平假名并括注汉字，例如 `だします(出します)`。不要擅自把礼貌体改成普通体。

优先使用「【普通形（な・の）】」这类紧凑总接续写法（大号粗体），括号内依次注明な形容词、名词现在肯定形的特殊接续。「普通形」概括四类词，括注标出例外：若该语法允许，则な形容词现在肯定的「だ」改为「な」，名词现在肯定的「だ」改为「の」；动词和い形容词照普通形接续。い形容词现在肯定形本来不带「だ」，不能说它“去だ加な”。否定、过去等仍按该语法真实规则展开，不能一律替换词尾。第38课应保留「【普通形（[だ]，[だ]）】」，不得因格式偏好改成「な・の」。

学习者原话留存：「确认入库，并将开头用大号粗体显示接续规则，优先考虑这种写法，例如【普通形（な・の）】表示动词和い形容词，な形容词和名词都是普通形，另外い形容词和名词的现在肯定形要去だ加な/の。」校对：最后一句的“い形容词”应为“な形容词”；原话保留，执行规则以上段校对说明为准。

学习者实际提供的原文必须原样保存，不能被校对内容替换。没有个人输出时，不虚构“学习者理解正确”等判断。视频例句、外部例句和自拟例句应标明来源类别；适量引用，优先用自己的语言概括。

### 中文释义分组与场景演示

学习者于2026-09-19更新规则：以已收集的语法信息照片上方中文释义为分组起点，判断合并后编写场景。保留原有大号总接续、核心解释及具体接续，在这些内容之后加入场景演示；不再编写“说话人的意图”，也不以“能否用一句共同意图解释”作为分组判断层级。以下规则替代此前按交际目的分组的要求。

- **读取照片中的中文释义。** 逐张目视核对本课已收集的语法信息照片，原样记录上方中文释义，通常按「；／;」拆出候选项并记录数量。不要根据卡片标题、自行改写的释义或例句数量代替照片计数；同一释义跨行不另算一项。文字模糊、遮挡或分隔不明确时，回查原视频或更清晰画面，不猜测。照片没有中文释义时如实记录，结合课程讲解与独立资料建立候选项并注明依据。
- **判断方法：** 先判断各候选释义是否只是同一意思的不同中文译法，是则合并；否则检查合并后是否会丢失重要含义或使用差异，不丢失则合并，会丢失则分别保留。例如“不可能……；怎么可能……”可合并；若合并会混淆事实判断与否定意志、推论与领会等重要差异，则分开。接续、人物、地点、话题或语气强弱不同，不单独作为拆组依据。合并涉及多项时须检查整组，不能仅因相邻两项近似就将全部串联合并。
- **按最终数量分组。** 无法合并时按候选释义数量分组，可以合并时按合并后数量分组；每组配一个代表场景。组数不预设为两组或三组，不因能写出更多生活情境就增加分组。
- **场景演示：** 每组直接写中文背景，交代人物关系及触发对话的事情，再通过人物对话展示对应释义的实际使用。每句对话先给出日语，随后用括号提供中文翻译；注明说话人，确保上下文自然。不添加“说话人的意图”或改名为“表达目的”等同类分析段落。
- **`<br>` 只用于日语行与其正下方中文译文之间。** 中文背景行、中文译文行以及段落之间的空行本身已经断行，不得再加 `<br>`；同一行也不得连写两个 `<br>`。补做已有卡片时一并检查并删去多余标签。
- **接续不在场景中重复。** 接续、礼貌体、缩约及词形差异在分组前的“核心与接续”统一介绍，组内及对话后不再重复分析。限制、易混项、双重否定及补充语气例句集中放在后续“语义边界”或“易混项及JLPT考点”，不按形式差异另立场景。
- **独立资料复核与遗漏检查。** 仍须核对至少两份独立教学正文，优先日本教学机构或教师的日文资料，用来验证释义、合并依据和使用限制，不照搬网站分类数量。若课程讲解或已核实资料包含照片未列的重要用法，将其补入候选项并注明来源，再执行同一合并判断。少见、跨级或不同结构的扩展可列为范围外并说明理由；关键内容无法核实则按问题处理流程处理。
- **记录分组与覆盖结果。** 在“来源与复核记录”保留照片路径／视频时间、中文释义原文、初始候选数、外部补充项、合并或保留理由及最终组数，并列出“候选释义或重要要点｜来源及支持内容｜最终分组或正文落点”。每项须可追溯，合并后仍要覆盖重要含义、限制及考点，不能只在来源中列出而正文遗漏。
- 场景中的接续、语义边界、语体及人物关系必须与已核实的规则一致；视频、外部来源或自拟场景应标明来源类别。自拟对话标注“自拟场景”，不得冒充视频原话或外部资料例句。

以下为结构模板，按释义合并后的分组重复；只有一组时无需编号。场景部分不附意图或接续分析：

```markdown
### 场景一：〈总结本组语法的使用场景，要求：先检索日本教育网站上的信息，找到使用日语解释该语法的内容，然后进行通用性的总结，使用中文显示，内容需要简练，紧凑〉

**场景演示（自拟场景）：**
〈中文背景：人物关系、当前情况及对话缘由〉

甲：〈日语对话〉<br>
（〈中文翻译〉）

乙：〈自然使用本用法的日语回应〉<br>
（〈中文翻译〉）
```

此要求适用于后续生成流程，不因更新规范而自动改写已有草稿或正式卡；修改正式卡仍须学习者明确“确认入库”。

## 写完后的复核

成稿后重新逐课阅读，不能把资料搜集过程等同于成稿复核。

- 接续表与截图、日语讲解及外部资料是否一致；词尾、助词及变形是否正确。
- 是否区分核心规则、常见倾向和例外，是否遗漏关键适用限制。
- 例句是否自然，是否真正体现本课用法，译文是否准确，是否误把自拟例句归给视频。
- 每组是否直接包含中文背景和人物对话，且体现对应释义；是否逐句先日语、后括号中文翻译并标明来源类别；是否没有“说话人的意图”及同类改名段落，场景中及对话后是否没有重复接续分析。
- **防止过细：** 是否从照片上方中文释义按「；／;」建立候选项，并依“同义译法／合并是否损失重要含义或使用差异”判断；是否误按接续、人物、地点、话题或语气强弱拆组，或重新引入共同意图判断。
- **防止遗漏：** 逐项核对覆盖记录，每个重要要点是否在正文中有实际落点，而非只列在来源中；合并后是否仍保留限制、对比和必要例句。特别检查否定意志与事实判断、推论与领会等实质差异，以及双重否定的范围、最终肯否方向和译文，不能为减少组数而抹去这些差异。
- 是否记录照片释义原文、初始候选数、必要补充项、合并／保留理由及最终组数；每个候选项是否有明确归属，实际场景组数是否等于最终保留的释义组数；是否误把网站的义项数、形式数直接当作场景数。
- 对话是否只在日语行末使用一个 `<br>`，中文背景、中文译文和段落是否没有多余的 `<br>`。
- 来源是否直接支持对应结论；分歧及处理方式是否写明。
- 每课是否恰有接续图和例句图两张原视频图片；例句图是否优先检查了视频后半部分并完整显示课程例句；两图是否属于正确课程、时间标注是否真实、是否放在“视频学习资料整理”中、接续图是否同时保留接续及必要说明、是否在不损伤教学内容的前提下尽可能裁去空白和人像、图片引用是否有效。
- 大号总接续是否逐字遵循原视频板书、没有私自添加助词或变体；视频中的 A、B 等结构符号是否在总接续及其解释中保留；逐词类展开的接续表是否改用具体类型，并按每种实际接续逐行书写。
- 元数据、编号、标题与课程序号是否一致；草稿是否仍为未确认状态，是否未设置正式复习日期。
- 复核记录写明核对了什么、修正了什么及实际限制，不以一句“已验证”代替证据。

程序检查只验证格式、链接等机械条件，不能代替语言内容复核。独立复核指对照独立资料，不默认要求启动其他代理。

## 问题处理与分批交付

- 某课关键接续或必要内容无法核实、资料冲突无法解决时，**直接列出问题，不交付该课卡片**。不要交付带关键“待核实”缺口的完整课程卡。
- 问题清单至少包含课程序号、语法名、原视频、具体疑问、已查资料及仍缺少的依据。说明继续处理需要什么证据。

## 审核、入库与复习

- 待确认卡保存到 `jlpt-notes/drafts/`。使用可解析元数据，明确未确认状态，不提前创建正式卡或确认事件，不预填下一次复习日期。

- 只有学习者明确说“确认入库”后，才按其指定的单课或批次创建或修改正式卡；批次范围不明确时先确认范围。
