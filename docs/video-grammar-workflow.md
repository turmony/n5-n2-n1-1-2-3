## 开始前

1. 阅读 `START-HERE.md`、`jlpt-notes/README.md`、本规范，以及本次参考或涉及卡片的 YAML/JSON 前置元数据。
2. 检查指定范围的正式卡、复习记录及目标路径的 Git 状态。开始前目标文件必须相对 `HEAD` 无未提交改动；已有不明修改或未跟踪的同名目标文件时，先列明并停止覆盖。确认现有卡编号、拟用编号没有重复或冲突。
3. 从播放列表核对课程序号、日语标题和视频 ID，建立本批对应表。注意分页、缺失视频和排序变化；不要仅凭相似标题猜测编号。
4. 阅读已有 N3 正式卡正文以了解元数据和通用格式；正文结构以本规范最新要求为准，旧卡中的接续表、语义边界、原视频例句、易混项及复核记录不得自动沿用。

## 获取课程材料

- 以原视频的日语讲解、日语字幕和板书为课程依据。字幕可能有同音错字、助词遗漏或断句错误，必须校对；不能把自动字幕当成准确原文。
- 每课优先提取 **0:01 的实际视频画面**，逐张目视检查是否清晰显示本课接续。
- **每个语法卡必须包含两张原视频图片：一张接续图和一张例句图。** 两图仅放在“视频学习资料整理”中，用于保留课程原始画面；接续内容不再转写到“核心”，视频例句也不再转录成“原视频例句”栏目。接续图用于展示本课接续及必要讲解板书；例句图用于展示视频中的课程例句，通常从视频后半部分的例句页提取。两张图分别标明真实时间、原图尺寸及裁切区域；不得用同一张图重复充当两类图片。
- 如果该时点是片头、遮挡严重或接续不完整，寻找其他清晰时点，必要时补充截图，标注各图实际时间，不把其他时点标成 0:01。
- 截图必须来自原视频，不得用封面、AI 重绘或根据字幕生成的示意图冒充。固定左上角，通过收拢右下角裁去底部空白与右侧多余画面；保留接续和必要板书，不重绘文字。记录原图尺寸与裁切区域。
- **截图不能仅仅显示接续内容。** 必须同时保留本课有助于理解的含义说明、例句或易混项等必要板书；不能为了裁掉人像，把画面缩成只有接续表的小块。此规则由学习者于2026-09-12补充。
- **在保证教学内容完整、清晰的前提下，尽可能裁剪掉空白和人像。** 优先选择老师让开板书、遮挡更少的实际时点，再固定左上角收拢右下角；若文字与人物重叠，优先换时点或用独立截图互补，不抹除人像、不重绘、不拼接。仍无法避免的遮挡应明确注明，不能用裁断主要板书来换取无人像画面。
- 保存截图文件、视频网址、实际时间和必要的获取记录。文档使用可追溯的图片引用，不依赖临时下载地址。
- 缺失字幕可尝试检查原视频画面或其他可用原始材料；关键内容仍无法核实，进入问题处理流程。

## Hagoromo 检索与最低限度内容检查

### 主要来源

- 语法功能、分组字段及正文例句以 [Hagoromo 文型检索](https://hagoromo-text.work/) 的实际检索结果为主要来源。
- 按原视频标题和板书确定本课需要查询的语法形式；一课包含多个并列形式、口语缩约或派生形式时，分别检索，不能只查标题中的第一个形式。
- 搜索结果页只用于定位条目。必须打开并读取实际条目中的「最上位意味カテゴリー」「中位意味カテゴリー」「意味」「くわしい意味記述」「派生語」和例句。
- 不再要求每课至少核对两份互相独立的教学资料。Hagoromo 未收录、检索结果无法对应课程、同形条目有歧义或关键内容明显缺失时，才按实际需要查阅原视频或一份可靠的补充日文资料；没有固定来源数量。
- 补充资料仅用于解决具体缺口，不恢复旧的逐项交叉复核流程。关键内容仍无法确认时，进入问题处理流程，不交付该课完整卡片。

### 检索与分组步骤

1. 使用课程中的实际语法形式搜索；方括号、圆括号、波浪线、汉字／平假名或可省略助词可能影响结果时，分别尝试去除标记或改用核心字符串检索，并记录最终采用的条目。
2. 确认条目确实对应本课语法和课程范围，避免误用同形异义、相邻语法或仅部分重合的条目。
3. 以「意味」和「くわしい意味記述」判断功能数量；同时参考两级意味カテゴリー。检索结果数量、派生語数量、接续差异、礼貌程度和口语缩约本身都不直接决定功能数量。
4. 多个形式若两级意味カテゴリー相同，且「意味」「くわしい意味記述」表达同一核心功能，应合为一个功能部分；只有核心意义或功能实质不同才分开。
5. 同一表面形式若检索结果明确给出多个不同功能，则分别编写。不能为了减少组数合并会改变肯否方向、逻辑关系、判断类型或表达功能的义项。
6. 每个功能从对应 Hagoromo 条目选择 3～5 个例句。例句不足3个、页面无法读取或例句与当前功能不匹配时，列出缺口，不自行编造补足。
7. 每个例句下面提供准确、自然的中文翻译。翻译由整理者完成并检查，不把机器翻译直接当作成稿。

### 网页获取

- 优先直接使用 Hagoromo 的站内搜索和条目页。需要抓取网页时，使用本机已安装的 Crawl4AI，命令行入口为 `crwl`；若页面依赖交互导致抓取不完整，可使用浏览器目视读取。
- 搜索摘要、AI 摘要或未打开的结果标题不能代替实际条目内容。
- 网页临时缓存放在仓库外的临时目录或已确认被 Git 忽略的目录中，不提交网页镜像和原始缓存。
- 记录实际使用的页面链接和查询日期，不虚构未打开的页面或未读取的字段。

## 正文格式与核心写法

待确认内容完整到可以审核后，直接写入正式卡目标路径并保持未提交。正文采用以下顺序：

1. 课程标题与待确认提示。确认前在正文开头明确标注“未提交待确认版本”；确认入库时删除该提示。
2. 学习者原始输出及理解校对；没有个人输出时使用“视频学习资料整理”。原视频两张截图放在此节，附视频链接、真实时间、原图尺寸、裁切说明和图片链接。
3. 核心。
4. 来源。

不再建立或显示以下栏目：

- “核心与接续”及任何总接续、具体接续说明或接续表格；栏目统一改为“核心”。
- “语义边界、适用条件与后项限制”。
- “原视频例句”；例句图仍保留在“视频学习资料整理”，但不把图中文字转录为独立例句栏目。
- “易混项及 JLPT 考点”。
- “来源与复核记录”；栏目统一改为“来源”。
- 旧的“中文释义分组与场景演示”、自拟场景和人物对话。

学习者实际提供的原文必须原样保存，不能被校对内容替换。没有个人输出时，不虚构“学习者理解正确”等判断。学习者提供礼貌体语法时，“核心”中的语法形式保留礼貌体；语法形式优先写平假名并括注对应汉字，例如 `だします(出します)`。

### 核心的分组与字段

- 语法有几个实质功能，“核心”就编写几个功能部分；只有一个功能时也保留清楚的功能标题。
- 功能数量按 Hagoromo 检索结果判断，主要比较「意味」和「くわしい意味記述」，并参考两级意味カテゴリー。
- 不按中文译法数量、例句数量、搜索结果数量、派生語数量、接续、人物、地点、话题、礼貌程度或语气强弱拆分功能。
- 多个检索条目表达同一核心功能时合并；不同条目若在逻辑关系、判断类型、肯否方向或表达功能上存在实质差异，则分别保留。
- 每个功能标题中“功能一：”后填写整理的语法图片中关于该语法的红色日文解释的中文翻译；该解释通常含有 A、B 符号。不得改用 Hagoromo「意味」原值或另拟功能名。
- 每个功能依次显示以下字段，字段名保留网站原文：
  1. 最上位意味カテゴリー
  2. 中位意味カテゴリー
  3. 意味
  4. くわしい意味記述
  5. 派生語
- 「最上位意味カテゴリー」「中位意味カテゴリー」「意味」的字段名各自独占一行；字段下按语法形式或采用条目分项排列，不把多个形式和值挤在同一行。
- 上述三个字段保留 Hagoromo 日文原值，并紧接着用小括号给出中文翻译，例如`原因・理由（原因与理由）`。
- 「くわしい意味記述」的字段名独占一行，字段下按语法形式或采用条目分项排列；每项保留 Hagoromo 日文原值，并紧接着用小括号给出忠实的中文翻译，不自行扩写网站没有提供的定义。
- 「派生語」以 Hagoromo 实际条目为准；未列出时明确写“未列出”，不猜测补充。
- 每个功能随后列出3～5个来自对应 Hagoromo 条目的例句。日语例句下一行直接给出中文翻译；不再另设“补充自然例句”栏目，不使用自拟例句填充数量。

### 来源

- “来源”只记录实际使用的资料，不写长篇复核过程、候选义项表、覆盖表或“已验证”式结论。
- 至少列出原视频和本课实际采用的 Hagoromo 条目链接；使用补充资料解决具体缺口时，再列该资料链接及其用途。
- 可记录查询日期和采用的条目名称，便于以后追溯；不得列入未打开或未实际使用的网页。

```markdown
# 来源

- [出口日語原视频](〈本课视频链接〉)
- [Hagoromo「〈采用的条目名称〉」](〈实际条目链接〉)（查询日期：YYYY-MM-DD）
```

以上要求适用于后续生成流程，不因更新规范而自动改写已有正式卡。正式卡路径中的未提交内容只是待确认工作区版本，不能据此创建确认事件或启动复习。

## 写完后的最低限度内容检查

- 课程编号、语法标题、原视频和 Hagoromo 条目是否对应，是否误选同形异义或相邻语法。
- 功能数量是否依据「意味」和「くわしい意味記述」确定；相同功能是否已合并，实质不同的功能是否仍分别保留。
- 功能标题是否采用整理的语法图片中红色日文解释的中文翻译；是否没有改用 Hagoromo「意味」原值或另拟功能名。
- 每个功能是否依次包含「最上位意味カテゴリー」「中位意味カテゴリー」「意味」「くわしい意味記述」「派生語」。
- 前三个字段是否按形式或条目分项排列，日文原值后是否有小括号中文翻译；是否没有把多个值写在同一行。
- 「くわしい意味記述」是否按形式或条目分项排列；每项是否保留 Hagoromo 日文原值并紧接小括号中文翻译；译文是否忠实于实际条目且没有自行扩写。
- 每个功能是否有3～5个来自对应 Hagoromo 条目的例句；每句中文翻译是否准确、自然并紧跟日语原句。
- 是否没有接续正文或接续表、“语义边界、适用条件与后项限制”、“原视频例句”、“易混项及 JLPT 考点”、自拟场景及旧的“来源与复核记录”。
- “来源”是否只列实际使用的原视频、Hagoromo 条目及必要补充资料，链接是否能追溯到对应内容。
- 每课是否恰有接续图和例句图两张原视频图片；两图是否属于正确课程、时间标注是否真实、是否放在“视频学习资料整理”中，图片是否清晰且引用有效。
- 元数据、编号、标题与课程序号是否一致；正文是否明确标注为未提交待确认版本，是否没有创建确认事件、改变既有复习日期或启动新的复习周期。

程序检查只验证格式、链接等机械条件，不能代替上述最低限度内容检查。

## 问题处理与分批交付

- 某课的课程范围、Hagoromo 对应条目、功能划分或必要字段无法确认，资料冲突也无法解决时，**直接列出问题，不交付该课卡片**。不要交付带关键“待确认”缺口的完整课程卡。
- 问题清单至少包含课程序号、语法名、原视频、具体疑问、已查资料及仍缺少的依据。说明继续处理需要什么证据。
- 原始资料与内部工作记录可以保留供续做，但不能作为已完成卡片展示。
- 其他已通过最低限度内容检查的课程可正常交付，清楚列出完成与未交付课程，避免将整批一概声称完成。
- 支持后续续做，复用已获取且适用的资料；没有新证据时不反复抓取或猜测填充。

## 审核、入库与复习

- 视频语法卡不再写入 `jlpt-notes/drafts/`。完整待确认内容直接写入 `jlpt-notes/grammar/n3/` 下的目标文件；新卡在 Git 中保持未跟踪，既有卡保持为未提交修改。Git `HEAD`代表最近一次已提交、可回退的稳定版本。
- 写入前必须确认目标文件没有本任务以外的未提交修改。既有目标不干净或同名新目标已经存在时，不得覆盖；先列出冲突。此检查使取消时可以安全恢复。
- 待确认正文开头必须有醒目的“未提交待确认版本”提示。元数据在审核阶段仅服务于预览和解析，不构成确认；不得提前创建确认事件，也不得改变既有确认日期、复习日期或启动新的复习周期。
- 提供目标卡入口及最低限度内容检查结果，由学习者审核。学习者提出修改时继续修改同一目标文件，同步受影响内容，重新检查并保持未提交；修改意见本身不等于确认或提交授权。
- 学习者明确取消时，既有卡只恢复本任务改动前的 `HEAD` 版本；新卡删除未跟踪的目标文件。只处理本任务创建且未被其他内容引用的截图及配套文件，不扩大恢复范围。
- 只有学习者明确说“确认入库”后，才按其指定的单课或批次删除待确认提示，补齐或更新正式卡元数据与确认事件；批次范围不明确时先确认范围。确认日期采用实际确认日，下次复习为确认日加七天，资料收集日和待确认版本写入日不能代替确认日。
- Git 提交与确认入库分别判断。待确认版本不得提交；确认入库后仍只有在学习者明确说“提交”或作出同等清楚的指示时才执行本地提交。若学习者同时明确要求“确认入库并提交”，可在同一轮完成；任何本地提交均不默认推送远程。
- 图片链接遵守项目 `AGENTS.md` 的“图片链接与入库校验”。正文从开始就按正式卡目标目录编写；每次写入前在内存中调用 `AssetIndex(root).check(destination, body)`，不再执行从 `drafts/` 到 `grammar/n3/` 的路径换算。元数据 `source.screenshot` 保持资料库根目录相对路径。
- 待确认版本写入正式卡目标路径后，以及确认入库完成后，均运行 `uv run python -m jlpt_notes validate-links --root jlpt-notes`。非零退出码表示校验失败，不得略过或宣称完成；代码块中的示例不当作图片链接检查，复杂写法无法无损解析时应明确报错，不猜测替换。
- 复习固定每七天一次；答错或不确定只能影响标签和未来出题侧重，不能安排提前复习。
- 如另行出题，仍遵守项目的 N2 非听力题型及四选项逐项解释规则；本流程不自动生成测验。

## 执行边界与本地工具

- 只执行学习者指定的课程范围，不自动继续下一批。
- Crawl4AI 已通过 `uv tool` 安装；调用命令行入口 `crwl` 抓取网页。需要编写 Python 脚本时，仍须通过 `uv run python <脚本>` 执行。
- 资料整理不夹带阅读器、安装、防火墙等程序或系统修改。如果图片无法在现有阅读器展示，报告依赖并另行讨论，不能为完成课程整理顺带改程序。
- 阅读器现已支持正文截图及缺图提示；文档引用与阅读器显示仍须分别验证、分别报告。链接校验通过不等于已完成 iPad 实机显示验收。
- Python 一律通过 `uv run python` 执行；需要临时依赖时可用 `uv run --with <包名> python`。不要直接调用系统 `python`／`python3`。
- 学习资料依照资料库 README 提交本地 Git，保留可恢复历史。视频语法待确认版本只保存在正式卡目标路径的工作区中，不自动提交；确认入库后等待学习者明确的提交指令，并且只暂存该次确认涉及的卡片、确认事件、截图及必要配套资料。原视频下载等临时缓存不作为正式学习资料提交。

本规范仅固定执行流程，不代表已开始生成第31—120课，也不代表任何课程已确认入库。
