# JLPT 网上题源组卷（quiz-generate）

题目必须建立在实际打开并核实的日本日语教育网站内容上。允许两种题源：完整保留的“网站原题”和根据网站例句制作的“例句派生题”。不得在没有教学来源的情况下自由编造考点、例句或答案；普通教学材料即可，不要求历年真题，未经核实不得冠以“真题”。

## 题源类型与不可替代规则

### 网站原题

- 必须实际打开原题及其对应答案，不能凭搜索摘要、模型记忆、其他 AI 输出或没有出处的题库选题。
- 保留原题题干、上下文、空格位置、全部选项和选项顺序。只允许调整本卷题号、Markdown 排版以及无歧义的选项编号映射，并记录映射。
- 来源缺答案、疑似多解、答案与语法或上下文冲突、OCR 无法确定文字时，排除该题并另找原题。不得以 AI 答案替代来源答案，也不得修改原题后继续标为网站原题。

### 例句派生题

- 只有实际打开的教学页面直接讲解目标语法并提供自然例句时，才可基于该例句派生题目。目录、搜索摘要、转载摘要或只偶然出现目标形式的页面不能作为例句来源。
- 允许把目标语法挖空、补写干扰项、把二选一或开放填空改成四选一，以及为提供必要语境而做有限调整；必须保留原例句、逐项记录改动，并明确标为“AI 根据网站例句改编”。
- 优先做最小改动。若必须重写主要命题内容、改变原句核心语义或补入无法由来源和语法卡支持的事实，弃用该例句。
- 干扰项必须是实际存在的日语形式，并具有与目标语法相近的接续、意义或易混关系；不得用乱码、明显不存在的形式或纯粹的词性错误凑数。考查语义时，尽量让各选项在表面接续上都成立。
- 题干必须提供足够语境锁定唯一答案。若两个以上选项在当前语境中都自然成立，修订派生题并重新审题；最多两轮修订及重新盲审仍不能消除多解则弃用。
- 派生题的正确答案、干扰项和解析均为 AI 编制，不能称为“来源答案”“网站解析”“官方题”或“历年真题”。

### 共同规则

- 优先日本日语学校、教育机构、出版社或有可核实教学背景的教师运营网站；不以 `.jp` 域名或日语页面单独判定可靠性。
- 默认依次检查以下题源，目标内容不足时才扩展到其他可核实的日本日语教育网站：
  1. [日本语能力试验官方网站](https://www.jlpt.jp/samples/forlearners.html)：官方问题例和题型基准；
  2. [日本語NET](https://nihongokyoshi-net.com/)：N5–N1 文法讲解与测验；
  3. [Attain Online Japanese](https://www.attainj.co.jp/online-japanese-tb/en/courseguide/jlpt/comprehensive-exercise.html)：N5–N1 综合练习、文法测试与模拟试验；
  4. [日本語の森](https://nihongonomori.com/)：N5–N1 课程、文法讲解和公开问题内容；
  5. [毎日のんびり日本語教師](https://mainichi-nonbiri.com/japanese-grammar/)：N5–N1 文法说明和大量例句，主要用于例句派生与语法复核。
- 付费、登录后或受访问条款限制的材料，只有在当前环境合法可访问且允许本次使用时才采用；否则记录为不可用，不绕过访问控制。
- 优先多站点取材，排除同题转载。任何题都必须能追溯到实际保存的网页摘录或截图。
- 现成题和可用例句都不足、来源不可访问或检索工具不可用时，报告已找到的数量、缺少的语法和原因；不得转为无来源自由编题，也不得擅自减少题数或扩大考点。

## 第 0 步：读取要求与格式

先读仓库 `START-HERE.md`、`README.md`、`AGENTS.md`、资料库 `jlpt-notes/README.md` 与相应卡片前置元数据。既有试卷、答案、题卡仅作文件格式参考，不作为无来源编题模板。若旧设计文档与本流程冲突，以本流程为准。

解析级别、目标语法或卡片范围、题数与题型。测验范围为 JLPT N5–N1 非听力题型；每卷使用一个明确等级，目标语法跨级时默认分卷，除非用户明确要求混合练习。用户只给语法时，优先采用同名正式卡等级；无对应卡时，根据可靠教学来源判定并在交付中说明。来源对等级划分不一致且会影响题目时，列明差异并请求用户决定。

沿用未指定题量与题型时的默认值：34题（形式选择20＋排序7＋完形7）；用户明确指定“20道选择题”则为20＋0＋0。课程编号只用于读取本地卡片，检索使用实际日语语法名称。

用户指定语法或卡片时直接检索，不再重复请求选卡确认；指定练习不改变七天复习日期。未指定时，参考 attempts.jsonl、最近报告薄弱项、已确认且到期卡片，先给出等级／卡号／考点／题型数量／理由的选卡建议，待用户确认后检索。

## 第 1 步：检索与来源取证

1. 阅读目标卡片的接续、语义边界和易混项，列出检索词，例如「ものだから 文法 練習問題」「をきっかけに 選択問題 解答」「に違いない 文法 例文」。
2. 使用当前环境可用的网页检索工具；有 Firecrawl 时按其搜索技能执行。搜索只用于发现页面，必须继续读取实际原题、答案或语法条目和例句；交互题可操作到显示答案的位置，PDF、图片和视频题须核对实际内容。
3. 先检索已有完整题目；不足时再检索直接讲解目标语法的自然例句制作派生题。语法只出现在干扰项中不算覆盖。
4. 为每个候选记录网站名、运营者或教学背景、标题、网址、原题号或例句定位、答案位置（如有）和访问日期。将相关原题与答案或语法说明与例句的实际摘录／截图保存至资料库 `quizzes/sources/<试卷名>/`；快照不可由模型重构。
5. 记录每题对应语法卡、匹配理由和题源类型。网站原排序题必须已有完整题块、星号位置和可核实顺序；原完形题须保留理解题目所需的完整篇章。派生排序或完形题须额外保存生成依据和全部改动。
6. 统计各卡、题型和题源类型覆盖。现成题不足时可以用合格例句派生补足；连合格例句也不足时报告缺口，不生成伪完整试卷。

## 第 2 步：制作试卷、答案和题卡

- 试卷：`jlpt-notes/quizzes/papers/YYYY-MM-DD-<level>-<主题>-test-N.md`，沿用既有标题和四选一格式；不含答案，尾部含空白“答案填写区”。按实际构成标注“日本教学网站原题选编”“日本教学网站例句派生练习”或“日本教学网站原题选编与例句派生练习”。逐题来源放在答案文件中，避免答题页暴露答案。
- 答案：`answers/<试卷名>-answers.md`，每题含题目、翻译、考点卡号、题源类型、正确项、正确接续、解析和四个选项的逐项解释。网站原题明确区分“来源答案／来源解析”和“AI 补充翻译与解析”；派生题明确写“AI 根据网站例句改编／AI 标准答案与解析”，不得冒充来源原文。
- 题卡：`questions/<LEVEL>-Q-XXXX.md`，沿用 JSON frontmatter 字段：id/revision/level/item_type/prompt/translation/tested_cards/conjugation/options/correct_option/correct_explanation/option_explanations；排序另有 recommended_order。新编号接续该级别最大号，不覆盖旧卡；完全相同的既有题可复用，但须如实说明重复练习。
- 每张题卡都增加 `source` 对象，并保留共通字段：`kind`、`site_name`、`publisher`、`title`、`url`、`locator`、`accessed_at`、`evidence_paths`（相对资料库根目录）。
  - 网站原题的 `kind` 使用 `teaching_exercise`；只有已核实才用 `official_sample` 或 `past_exam`。另记 `answer_url`、`answer_locator`、`original_answer`、`option_mapping` 和 `adaptation`（仅排版／编号映射）。
  - 例句派生题的 `kind` 使用 `derived_from_example`。另记 `original_example`、`transformations`、`answer_basis` 和 `distractor_basis`；没有来源答案时不要填写或伪造 `original_answer`。
- 中文翻译与补充解析不能反向改变网站原题或来源答案。派生题可以为唯一解做有限调整，但每次调整都要写入 `transformations` 并重新审题。
- 对正文中的本地图片按所在 Markdown 目录写相对链接，遵守仓库图片校验规则。只写练习资料，不改正式语法卡或复习日期。

## 第 3 步：来源核对与机械校验

网站原题逐字对照保存证据，确认空格、上下文、选项文字与顺序、来源答案映射一致。例句派生题逐题对照原例句和生成记录，确认目标语法、核心语义和必要语境仍受来源支持，且所有改动已披露。两类题都要确认每题四项解释齐全，并按来源定位和内容共同查重。

再运行现有校验器，例如20道形式选择题：

```text
uv run python .claude/skills/quiz-generate/scripts/validate_quiz.py --paper <试卷路径> --answers <答案路径> --structure 20,0,0 --level <N5|N4|N3|N2|N1>
uv run python -m jlpt_notes validate-links --root jlpt-notes
```

校验器检查结构和文件一致性，**不会自动证明题源真实性、派生题唯一解或语法正确性**；不得用“机械校验通过”代替人工来源核对与独立审题。图片链接校验非零时列出问题，不宣称完成。

网站原题有内容问题只能替换，不能改写后继续当作原题。派生题发现问题时可依据原例句和语法卡修订，记录改动后重新执行全部检查。最多两轮修订及重新盲审仍有错误则弃用并报告缺口。不得改写题干来绕过查重。

## 第 4 步：独立审题

派独立子代理盲答，第一阶段只提供试卷全文及目标语法卡目录，禁止读取答案文件、题卡、来源答案和生成记录。要求逐题输出答案、理由、信心；排序题拼出完整句，并指出任何多解或不自然之处。

第二阶段按题源类型复核：

- 网站原题：提供来源答案和证据定位。持续分歧、多个自然答案或出处不可靠时直接排除，不能修改后继续标为原题。
- 例句派生题：提供原例句、教学条目和完整生成记录。核查目标语法是否匹配、改动是否最小、干扰项是否真实且只有一个自然答案；发现问题可修订并重新开始盲审，最多两轮，仍有分歧则弃用。

不得让用户替有缺陷题目决定标准答案。

## 第 5 步：交付

说明试卷、答案、题卡及来源证据路径；报告题目数量、等级、各卡覆盖、各网站数量、网站原题／例句派生题数量、来源核对、机械校验和独立审题结果。没有执行的步骤必须如实标注，不得编造“全绿”、来源答案或网站出处。

仅在请求的数量、题型和范围均满足且检查通过后，按既有习惯提交本地 Git：`feat: 添加 <卷名>（日本网站题源练习，<题数>题，覆盖<卡段>）`。原题和合格例句合计仍不足时只报告候选清单和缺口，等待用户决定后再正式组卷。

## 维护

用户只要求修改 skill 时，不执行检索组卷、不创建试卷或作答记录。今后新增来源类型或机械校验能力时，要同时修改校验脚本及有意义的回归测试；文档中不得声称尚未实现的自动来源、语法或唯一解校验已经存在。
